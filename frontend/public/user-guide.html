User Guide

Agile Comrade watches your active and upcoming Jira sprints, scores delivery risks in real time, and drafts AI mitigation plans — so you can act before a sprint slips.

MVP / demo software. Agile Comrade is an MVP decision-support tool for Scrum Masters and Delivery Managers: it surfaces potential delivery risks early so teams can investigate and act sooner. AI results are signals, not guarantees — they may contain false positives, miss risks, or lack context.

1. Get started: connect your workspace

  1. Open Settings and fill the profile form:
    • Jira Cloud URL — e.g. https://your-domain.atlassian.net
    • Jira email + API token — create one at id.atlassian.com/manage-profile/security/api-tokens
    • Project keys — comma separated, e.g. PFIN, MOS
  2. (Optional) pick an LLM provider: Gemini or OpenRouter, with your API key. Without it everything still works using built-in rule-based scoring.
  3. Click Test Connection to verify auth, story-point field detection and each project's sprint status.
  4. Click Save Profile. Your access token is stored only in this browser.
Secrets are encrypted at rest; teammate names & emails are pseudonymized before any data reaches AI providers. See the privacy notice.

2. The dashboard

Active Sprints (Risk Scanner)

One card per active sprint with its overall risk score and top risk type. Click Details → to open the sprint view.

Sprint Details

  • Issues are listed with severity, risk type, detection reason, affected stories and live status.
  • Use Mitigation Plan with AI (current sprint) or Scan with AI (future sprint) — the button sits above the Work Items, and the AI Mitigation Plan card (action items, owner, timeline, success criteria) appears directly below it.
  • If your LLM provider is unreachable, an amber rule-based fallback note appears inside the plan card and the plan is built from built-in heuristics instead.
  • 💬 Draft Message writes a polite follow-up for the assignee. Hit 📋 Copy and paste it into the Jira ticket yourself — the app never posts to Jira.

Future Sprints (readiness)

Before planning begins, run Scan with AI on an upcoming sprint to surface early warnings: unassigned work, missing story points, thin acceptance criteria, overloaded assignees, hidden dependencies.

Velocity Trend & Portfolio Overview

Trend views of completed story points per sprint and a cross-project executive summary, including an AI stakeholder report you can paste into updates.

3. Data freshness

The dashboard reads from a cached snapshot refreshed automatically every few minutes, or immediately via Sync Now in the top bar.

4. Troubleshooting

SymptomFix
"No active current sprints"Start/schedule a sprint in Jira for the configured projects, then Sync Now.
AI analysis fails or is slowLLM calls are capped ~45s; if the provider times out the app falls back to rule-based results automatically. Retry or check your LLM key.
"Rule-based fallback" note inside the planAI was unavailable — the mitigation plan comes from built-in rules and may be less specific. Check your LLM key in Settings and retry with Mitigation Plan with AI / Scan with AI.
Story points show 0Your Jira uses a custom field. Set it in Settings (customfield_10102-style); Test Connection verifies it.
A project fails the Test Connection checkCheck the project key spelling and that your Jira account can browse that project.

5. Good to know

  • This is MVP software — avoid connecting production workspaces (see privacy notice).
  • Multiple profiles are supported; switch between them from the top bar. Each browser keeps its own tokens.
  • Deleting a profile in Settings erases its server-side data immediately.
